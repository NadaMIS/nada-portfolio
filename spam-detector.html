Spam Detection App

A text classifier chosen on the mistake users mind most, and shipped as a web app where anyone can paste a message and get an answer.

  • NLP
  • Machine learning
  • Deployment
~5,600messages, about 1 in 8 spam
131 / 150spam messages caught
10real messages wrongly flagged
3models compared

The problem

With so little spam, a model can score high accuracy while missing most of it. Both mistakes matter, but not equally: letting spam through is annoying, while hiding a real message can cost someone something important.

My role

Solo project: text cleaning, features, model comparison, and the Flask app and interface.

  • Python
  • NLTK
  • scikit-learn
  • SMOTE
  • Flask

How I approached it

  1. Cleanlowercase, strip symbols and stopwords
  2. VectorizeTF-IDF word weights
  3. BalanceSMOTE on training data only
  4. ShipFlask app with probability and trigger words

What I found

Naive Bayes gave the best balance.

KNN almost never flagged a real message but missed over a third of the spam. The Decision Tree caught more spam but hid 32 real messages. Naive Bayes sits closest to the ideal corner.

Where each model's mistakes land.

Of the 150 spam messages in the test set, what each model caught and missed, next to the real messages it hid by mistake.

Shipped as an app, not a notebook.

The model runs behind a Flask endpoint. Besides the verdict, the app shows the spam probability and the words that triggered it, so a non-technical user can see why.

Recommendation

  1. Choose on the trade-offJudge models on missed spam and hidden messages, not accuracy.
  2. Explain the answerProbability and trigger words make the verdict easy to trust or question.
  3. Balance only training dataTest results then reflect the real mix of messages.

Limits

Limits: English SMS only. The training notebook still needs to be added to the repository so results can be reproduced.
