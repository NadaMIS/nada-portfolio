01 / The product question

Can a model protect the inbox without getting in the way?

The project built a machine-learning classification system to distinguish spam from valid messages, then connected that model to a web interface where a user could enter text and receive an instant classification.

That last step matters: the work moved beyond notebook experimentation into a usable interaction.

03 / The data challenge

Spam was the minority.

The dataset contained roughly 4,900 valid messages versus about 700 spam messages. That imbalance matters because a classifier can look deceptively strong by favoring the majority class.

TF-IDF represented message content numerically, while SMOTE was used to increase minority-class representation during training.

05 / Read the errors

A false positive has a human cost.

For the selected Naive Bayes model, the confusion-matrix counts show a useful trade-off: it caught 131 spam messages while only falsely labeling 10 valid messages as spam.

That makes model evaluation more concrete than a single accuracy score: missing spam is annoying, but incorrectly hiding a legitimate message can also be costly.
